振幅表示ブロック

span 内の量子ビットを測定せずに、状態ベクトルの複素振幅 (大きさ + 位相) を可視化する振幅表示ブロック (`表示ブロック` の定義は AGENTS.md 用語集と design-system §04 参照)。 確率表示ブロックが |α|² (周辺確率) を線形バーで描くのに対し、本表示ブロックは α = re + i·im を 横断プリミティブ 振幅円 (輪郭円 + 振幅円盤 + 円盤境界線 + 位相針) で描く。 span 上限は 16 量子ビット (Quirk と同じ。216 = 65 536 outcomes)。 配色 (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) は状態ベクトルパネルと完全に揃える。 Quirk の振幅表示ブロックの見た目を、Flexoki + WebGPU の表示ブロックとして定義する仕様書。

§ 00 複素振幅の視覚表現選定根拠

本表示ブロックは、複素振幅 α = re + i·im を極座標として読み替え、 大きさ mag = |α| を円盤半径、位相 phase = atan2(im, re) を針の向きで表す。 円盤の面積は mag²、つまり測定確率に比例するため、確率の量感と位相パターンを同じセル内で同時に追える。 位相 0 は状態ベクトルパネルと同じ真上に揃え、画面全体で「真上 = 正の実数」という読み方を統一する。

批評 · 代替表現との比較

候補採否判断
極座標: 円盤半径 + 位相針採用大きさと位相を分離して読める。振幅円と状態ベクトルパネルの語彙を共有でき、cellPx が小さいときは針だけを省略しても確率の量感が残る。
直交座標: 実部 / 虚部の 2 本バー不採用実部と虚部の符号は直接読めるが、位相パターンを目で追うには 2 本の長さを合成して読む必要がある。多数セルを並べたときの干渉模様が見えにくい。
フェーザ: 中心から (re, im) へ伸びる 1 本矢印不採用1 オブジェクトで簡潔だが、mag が小さいセルでは矢印そのものが短くなり、位相も大きさも同時に失われる。円盤なら小振幅でも確率の量感を残せる。
色相: 位相を色で表す不採用高密度表示への移行は自然だが、Flexoki Light の意味付き色体系と衝突しやすい。色覚差にも依存するため、本仕様では形状で位相を表す。

この選定により、本表示ブロックは「確率も読めるが、主目的は位相を含む複素振幅のパターンを読むこと」に位置付ける。 確率だけを高密度に読みたい場合の使い分けは § 01 の判断表で定義する。

確率表示ブロックとの使い分け

読みたいもの推奨理由
位相パターン、干渉、複素振幅そのもの振幅表示ブロック針の向きで位相を追える。円盤の面積で確率も同時に読めるため、QFT や位相回転後の状態を観察しやすい。
大きな span の確率分布形状確率表示ブロック線形バーは幅 40 px のまま縦方向に圧縮できる。span 12〜16 のようにセルが極小になる場合、位相より分布の山谷を読む用途に向く。
1 セルの正確な複素値振幅表示ブロックポップオーバーで Amplitude: / Probability: / Phase: を状態ベクトルパネルと同じ行構成で確認できる。
測定確率だけを数値で確認確率表示ブロックポップオーバーが確率値に絞られ、位相情報を読ませない。確率だけを確認する作業では情報密度が低くて済む。
span 外とのもつれを見つける密度行列表示ブロック振幅表示ブロックは非コヒーレント状態で確率だけを表示し、ポップオーバーも 3 行構造を維持する。混合性や非対角成分を見たい場合は密度行列表示ブロックを使う。

全 span (1〜16) の一覧は § 02 サイズ別の見た目、配色 / セル描画モデル / 投影 / GPU-only 不変条件は § 04 以降を参照。

§ 02 サイズ別の見た目 (1〜16 量子ビット、動くモック)

span を 1〜16 (上限) 全部並べた参考レンダリング。測定結果数 n = 2span を w × h グリッド (w = n === 2 ? 2 : 1 << floor(log2(n)/2)) に配置する。 位相の原点 (needle の向き) は state panel と同じ「phase = 0 = 真上」 (cell 中心からの方向 = (−sin(phase), −cos(phase)))。 各セルにマウスを乗せると、状態ベクトルパネルと同じ |bin(k)⟩ decimal k / Amplitude: / Probability: / Phase: のポップオーバーを表示する (詳細は § 08)。 cell 寸法 (cellPx) が小さくなるにつれてレイヤを段階的に省略する。閾値 (§ 06 参照): cellPx ≥ 12 = needle + outline + disk / cellPx ∈ [3, 12) = outline + disk (disk は半径閾値を満たすセルのみ) / cellPx < 3 = heatmap。cell 間の区切り線は描かず、matrix 全体の外枠だけを描く。 本番の cellPx は § 05 表参照、span 16 でも最小 3 px なので heatmap は本番では発生しない。ただし cellPx ≈ 3 では § 06 の半径式により円盤半径が 0 に近づくため、円は点状または外枠だけに近い表示になる。 下のモックは表示の都合で 320 px に縮小しているので、モックでは span 13〜16 が cellPx ≤ 2 となりヒートマップモードに入る。 heatmap は通常表示の必須経路ではなく、将来さらに小さいセルを許容した場合の仮想的な退避描画として扱う。

実行前プレースホルダ (シミュレーション未実行の状態)

回路に振幅表示ブロックを配置しただけで、まだシミュレーション (▶ Run) を実行していない段階で表示する仮の見た目。 計算結果がまだ確定していないため振幅値は存在せず、セル領域が背景と同化すると「未実行」なのか「壊れている」のかを判別しにくい。 この空白を「実行待ちであることを伝えるプレースホルダ」として明示的にデザインする。

  • 背景 (placeholder fill) — purple-100 (#ECE1F3) の薄い紫で塗る。 本デザインシステムでは「未確定 / 進行中」を表現する色として紫を採用しており (drag preview = purple-600、ホバー枠 = purple-400)、 実行前の振幅も 0 (赤系) と 1 (青系) の中間に位置する未確定な値として同じ紫系統で表す。 色相は drag/hover で使う濃い紫よりさらに淡くして、「進行中アクション」と「結果待ちの静止状態」を区別する。
  • outline 円 — ui-2 (#DAD8CE) の薄いグレー。これは「振幅 ≈ 0」のときの既存配色 (state panel state_outline_zero) と同じ token を流用するので、追加の色定義は不要。stroke 太さ・半径は通常時と同じルール (cellPx ≥ 24 で 2 px、それ未満で 1 px、半径 = cellPx/2 − stroke/2 − 1.5 px)。
  • disk / needle — 描かない。振幅値そのものを持たないので、disk (大きさ) も needle (位相) も意味を持たない。
  • frame — 通常時と同じ ui-2 1 px の外枠を引く。これにより「ゲートとしての箱の輪郭」が背景 bg-2 と区別できる。
  • ホバー / ポップオーバー — 実行前は cell 単位のポップオーバーを出さない (表示すべき数値が無い)。ゲート全体のホバー枠 (purple-400 4 px) は通常時と同じく出し、リサイズハンドルは端ごとの表示可否判定に従う。
  • 遷移 — Run を押した瞬間、placeholder layer (薄紫背景 + グレー outline) を 150 ms ease-out でフェードアウトしつつ、通常の disk + needle 描画にクロスフェードする。フェード中は cellPx の判定 (§ 06) も通常通り適用する。

可変幅 (56 × cols − 16 px) の配置要件

振幅表示ブロックは 2D 行列の縦横バランスを保つため、span に応じた可変幅を採用する。 配置時の見た目・衝突判定・ホバー枠・ドラッグ中プレビューは、常にこの可視矩形全体を対象にする。

  • 可視矩形 — 幅は 56 × cols − 16 px、高さは 56 × span − 16 px。矩形内に他の回路要素が重なる配置は不可。
  • ドラッグ中プレビュー — 本体と同じ幅・高さで表示する。背景は通常ゲートのドラッグプレビューと同じ purple-600 を使い、セル内の白地・円盤・輪郭・位相針の色は維持する。
  • ホバー表示 — cell hover は対象測定結果の outline 円周だけを purple-400 に置き換える。cell hover 中は表示ブロック全体の矩形ホバー枠を出さない。
  • リサイズ — 上下ハンドルで span だけを変更する。幅は span から自動で決まり、左右の幅ハンドルは置かない。上下それぞれの表示可否とドラッグ停止条件は resize-handle.html § 06 に従い、span 1 では空いている端だけ表示し、他の回路要素に重なる手前で止める。
  • 保存形式 — "Amps3" のように span を持つ 1 トークンで表す。表示幅の列数は保存形式ではなく描画上の幅として扱う。

§ 06 セル描画モデル (state panel と同じ 4 層)

qni-webgpu の状態ベクトルパネルと 同じ 4 層モデルを 1:1 で踏襲する: outline 円 + 振幅 disk + disk 境界線 + 位相 needle。 Quirk の確率正方形 / 対数円は冗長 (disk の半径 = mag、面積 ∝ mag² で確率値も読める) なので不採用。 α = re + i·im, mag = |α| = √prob。

この極座標モデルの利点は、円盤の面積で確率の量感を保ちつつ、針の向きで位相パターンを追える点にある。 直交座標バーは実部 / 虚部を直接読める一方で、多数セルの干渉模様を読むには 2 本のバーを頭の中で合成する必要がある。 フェーザ 1 本だけの表現は簡潔だが、小振幅では矢印が短くなり、位相も大きさも同時に失われる。 そのため、本仕様は § 00 の通り「円盤で大きさ、針で位相」を分担する。

(1) back fill — セル背景。通常時は bg (#FFFCF0)。drag preview 中だけ円の外側を purple-600 (#5E409D) に差し替え、outline 円の内側の白地と disk / outline / needle 色は維持する
(2) outline 円 — セル中央、半径 = max(0, cellPx/2 − stroke/2 − 1.5 px) (matrix 外枠へ触れない範囲で最大化する)。stroke は cellPx ≥ 24 で 2 px、それ未満で 1 px。円形状の表示条件: cellPx ≥ 3。 mag > 1e-6 なら tx-2 (state panel の state_outline)、≈ 0 なら ui-2 (state_outline_zero)。cellPx が 3 px 付近では半径が 0 に近づくため、視覚上は点状または外枠だけに近い表示になる。cell hover 時は正方形枠ではなく、この outline 円周を purple-400 で上書きする。
(3) 振幅 disk — 中心 = セル中心、半径 r = mag × inner_radius (= mag × (outline_radius − stroke/2)、mag = 1 で outline の内側ギリギリまで広がる)。 blue-200 fill (state panel の state_fill、Quirk #8FF と等価)。 加えて blue-400 (確率表示ブロックのバー右端と同じ) でinset の 1 px 境界線を引く: ① 半径 r で fill ② 半径 r − 0.5 で stroke。stroke の外端が r に一致するので視認性は上がるが disk 面積は変わらない。閾値: r > 0.3 で fill、r ≥ 1.5 で stroke も追加
(4) phase needle — セル中心から方向 (−sin(phase), −cos(phase)) = (−im/mag, −re/mag) へ長さ inner_radius の線分。 tx stroke (outline と同じ太さ: cellPx ≥ 24 で 2 px、それ未満で 1 px)。 描画条件: cellPx ≥ 12。それ未満では省略 (cellPx ∈ [3, 12) は円形状を維持しつつ、outline / disk は半径閾値に従う。cellPx < 3 はモック限定 heatmap)。 位相 0° = 真上、反時計回りに π/2 (= 左)、π (= 下)、−π/2 (= 右)。 状態ベクトルパネルと同じく、位相 0° を真上に取る。
(5) frame — matrix 全体の外枠だけを ui-2 1 px で描く。cell 間の区切り線は描かない (円と円の間は bg のまま)

状態ベクトルパネルとの差分: 色トークン (blue-200 fill / blue-400 disk border / tx-2 outline / tx needle) と disk 半径計算式 (mag × inner_radius) は同一。ただし以下の点で異なる:

  • cell を矩形 grid で密に並べる (state panel は cell 間に 3 px gap あり)
  • outline 表示条件: mag > 1e-6 で tx-2 / ≈ 0 で ui-2。10 量子ビット 一様振幅 (prob = 1/1024) のような小さいが非ゼロの振幅も non-zero outline として扱う
  • layer 合成順序: 本仕様は frame → outline → disk → disk border → needle (state panel は fill → disk border → needle → outline 合成)。cell 間の区切り線は描かない
  • phase lock cell の別マーカーは引かない (state panel は phase lock 概念がない、本仕様も Quirk の赤マーカーを不採用)

描画順序

描画は 背景 → matrix 外枠 → outline 円 → 振幅 disk → disk 境界線 → 位相針 の順に合成する。 cell 間の区切り線は描かず、位相針を最上層に置くことで小さなセルでも方向を読み取りやすくする。

§ 07 phase lock + incoherent state

phase lock — 主要振幅を位相基準に

最大振幅を持つ測定結果を位相基準に選ぶ。 その振幅の位相 θ = atan2(im, re) を全 ket から e−iθ で打ち消し、 phase lock 後の振幅は実数正 + 虚部ゼロに正規化される。これで「全体に同じ位相を掛けたとき見た目が変わらない」 = 量子状態の物理的等価性を視覚化に反映する。

phase lock cell に別マーカーは引かない。state panel と同じく needle が真上 (位相 0) を向いている cell を見れば自然に lock 位置がわかる、というのが基本方針。 Quirk 原版の赤い水平線 + 'fixed' ラベルは (a) needle 方向との視覚的衝突 (Quirk は phase 0 = 右、本仕様は phase 0 = 上)、(b) state panel に同等マーカーが無いため UI が分散する、の 2 点で不採用。 span == 回路全体の量子ビット数 のときだけは phase lock を無効にする (「全体相」を持つ意味がないため、Quirk 同挙動)。 phase lock は span が回路全体を覆うとき無効化し、正規化のみで位相回転しない。

incoherent state — entangled で振幅未定義

span 内の量子ビットが span 外と entangled しているとき、純粋状態としての振幅は定義できない (reduced density matrix のみ計算可能)。 Quirk は coherence 指標 quality = denormalizedQuality / unity / incoherentUnity を計算し、 quality < 0.99 で incoherent と判定する。 初期値は Quirk 互換の 0.99 とするが、これは固定不変の物理定数ではない。 実測で純粋状態の false-incoherent が確認される場合は閾値を見直す。

  • matrix は ket ではなく incoherentKet = sqrt(reduced_diag) (実数のみ) を描く
  • outline 円は通常通り描く (情報量を保持)、disk は alpha 0.45 で薄塗り「振幅未定義 / 確率のみ」を示す
  • phase needle は描かない (虚部が無いので位相は 0、線が意味を持たない)
  • ゲート下に "incoherent" を red-600 でフェードイン (1 − indicatorAlpha 透明度)
  • ホバー時ポップオーバーは § 08 と同じ 3 行構造を維持し、Amplitude: と Phase: は —、Probability: だけに確率値を表示する

measure 済み列での挙動 (Quirk と仕様が異なる)

qni と Quirk で capture 順序が異なる:

  • Quirk: 列処理の前に display capture → measure された量子ビットがあっても collapse 前の純粋振幅を表示。「deferred measurement」の解釈で、本体下に "(w/ measure defer)" / "(assuming measurement deferred)" を red-600 でフェードイン。
  • qni: 測定後の状態を表示する。span 内に測定済みの量子ビットがあれば、測定結果に対応する確定状態として見える。

本仕様では「測定後の状態を素直に表示する」を採用。本体下の "incoherent" 以外の補足テキストは出さない。

§ 08 ホバー時ポップオーバー

振幅表示ブロックのセルは、状態ベクトルパネルと同じ振幅円を表示する。 そのため、ホバー時の内容、数値形式、三角形の近接配置は独立仕様 振幅円ポップオーバーを正とする。 本ページでは振幅表示ブロック側の前提と GPU 描画経路だけを補足する。

内容仕様振幅円ポップオーバー § 02。|bin(k)⟩ decimal k 見出しと Amplitude: / Probability: / Phase: の 3 行を使う。
配置仕様振幅円ポップオーバー § 03。対象セルの右側ではなく、対象の輪郭円を基準に上側へ近接配置する。
非コヒーレント状態振幅と位相は —、確率だけを表示する。raw / log の 2 行カードへは切り替えない。
本番経路値は GPU storage buffer から overlay shader で直接描画し、CPU へ読み戻さない。詳細は § 09 のポップオーバー描画メモを参照。

§ 09 GPU-only 不変条件と検証方針

本番 UI 経路では、複素振幅・確率・位相・ポップアップ内の数値を CPU へ毎フレーム読み戻さない。 量子状態の計算、表示ブロック本体の描画、ホバー時ポップアップの値表示は GPU 上で完結させる。 CPU 側は配置・サイズ・ホバー対象などの UI 入力だけを渡し、状態ベクトルや測定確率そのものを計算しない。

  • 表示前 — 計算結果がまだ無いときは § 02 の placeholder を描く。
  • 通常表示 — coherent state は円盤 + 位相針、incoherent state は薄い円盤 + “incoherent” 表記で区別する。
  • ポップアップ — coherent / incoherent の行構成は § 08 に従う。画面端では ポップオーバー共通仕様 の反転・余白規則に従う。
  • 検証 — 代表 span、placeholder、incoherent、ホバー時ポップアップを Playwright とスナップショットで確認する。テスト用の on-demand 読み戻しは許容するが、本番 UI の毎フレーム経路には含めない。

CPU は vertex バッファを作らない。ゲート配置 (cell サイズ) が変わったときに更新する vertex は cell quad の四隅と uv だけ (各セル fragment shader が cell index を知るための instance buffer 相当)。これは ゲート placement / resize 時だけ rebuild。

ポップオーバーの値も GPU 描画 (読み戻し無し、glyph atlas + overlay shader)

ホバー時ポップオーバーの数値 (Amplitude: / Probability: / Phase:) は本番 UI 経路なので、GPU-only ルールに従い読み戻ししない。 外装、見出し、アイコン、固定ラベルは振幅円ポップオーバー仕様と同じクロムを使い、値だけを glyph atlas + overlay render pass で GPU 上から直接合成する。 非コヒーレント状態でも行構成は変えず、振幅と位相の値欄には — を描く。

必要なリソース

  • glyph_atlas: texture_2d — ASCII 数字 0..9、記号 + − . i %、単位 °、未定義値の — を Geist Mono で焼く。ラベル文字は状態ベクトルセルと同じ固定描画でよい。
  • amplitude_result — § 09 の compute pass 出力 storage buffer (ket / incoherent_ket / quality / phase_lock_index)。fragment shader は quality < 0.99 で incoherent_ket を読み、それ以外は ket を読む。
  • popup_uniform: PopupRenderInput — ホバー中の測定結果 hovered_k: u32、ポップオーバー位置、三角形の向き、表示 / 非表示フラグ。ホバー判定は CPU が座標から hovered_k だけを渡し、値そのものは渡さない。

overlay render pass

状態ベクトルセルと同じ 3 行の値欄を描く。非コヒーレント状態の確率は incoherent_ket[k]² を使い、振幅と位相は未定義記号にする: 

// fragment shader (popup overlay) — 3 行の値欄だけを GPU で描く
@fragment
fn fs_popup(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    if (popup.hovered_k == 0xffffffffu) { discard; }
    let k: u32 = popup.hovered_k;
    let q: f32 = amplitude_result.quality;

    if (q < 0.99) {
        let sqrt_p: f32 = amplitude_result.incoherent_ket[k];
        let prob: f32 = sqrt_p * sqrt_p;
        return draw_three_value_rows(
            uv,
            format_dash(),
            format_signed_percent(prob, 4u),
            format_dash(),
        );
    }

    let amp: vec2<f32> = amplitude_result.ket[k];
    let prob: f32 = dot(amp, amp);
    let phase_deg: f32 = atan2(amp.y, amp.x) * 180.0 / PI;
    return draw_three_value_rows(
        uv,
        format_complex_signed(amp.x, amp.y, 5u),
        format_signed_percent(prob, 4u),
        format_signed_deg(phase_deg, 2u),
    );
}

振幅円ポップオーバー仕様との共有

  • 外装と配置 — 振幅円ポップオーバー仕様 § 03 の配置を使い、三角形の先端を対象の輪郭円から 4 px に保つ。
  • 固定ラベルとアイコン — Amplitude: / Probability: / Phase: と 3 つのアイコンは同仕様 § 02 に従う。
  • format helper — format_complex_signed(re, im, 5)、format_signed_percent(prob, 4)、format_signed_deg(deg, 2)、format_dash() を共有する。確率表示ブロック固有の dB 表示はここでは使わない。

振幅表示ブロックのポップオーバーは、振幅円ポップオーバー仕様に「表示元が回路上のセルである」差分だけを足す。数値の本番描画は GPU storage buffer から直接行い、CPU への状態値読み戻しは導入しない。

読み戻しはテスト専用 API に限定: read_amplitude_cell(gate_id, k) は #[wasm_bindgen] で JS テストから呼ぶ async API としてのみ提供 (Playwright で Amplitude: / Probability: / Phase: の正しさを確認する用途)。本番 UI 経路からは一切呼ばれない。 これは AGENTS.md の例外条項 (テストハーネス向けの on-demand readback) に該当。

Quirk の探索ロジック m > best * 10000 は「明らかに大きい測定結果だけ採用、拮抗時は index 0 を保つ」。 これは振幅が小数点 4 桁オーダーで揺らぐ場合に lock 先が安定するメリットがある一方、span が大きいときに「実質的な最大値」を見逃すケースが出る。 例えば span 8 の QFT|001⟩ では全 256 測定結果が mag² = 1/256 ≈ 0.39% で均等になり、best × 10000 条件を満たす測定結果は存在せず lock index = 0 で固定される。 これは「均等位相分布では位相回転をしない」という意味になるが、ユーザは「lock index が真に最大の測定結果を指している」と期待する。 テスト計画 § 11 にこのケースが含まれているのは良いが、本セクションでは Quirk 互換であるという根拠だけで採用されている。qni-webgpu 独自の制約 (cellPx ≥ 12 で needle が見える span 1〜8)に対して最適化された探索ロジックを検討する余地はある (例: m > best × 1.1 など 10 % 程度の差で更新)。

    1. control_mask = 0 で無条件、全要素が集約対象
    2. |1⟩ control で control_value bit が立っている state_index のみ採用
    3. |0⟩ anti-control で control_value bit が 0 の state_index のみ採用
  7. post-measure 挙動 (qni 仕様、Quirk と異なる) (Rust, #[test]) — span 内に measured wire を含む列で、display capture が collapse 後の古典化 amplitude を返すことを assert (Quirk の "deferred measurement" とは値が異なる、§ 07 で決定)。
  8. incoherent state 検出 (Rust, #[test]) — span 外と entangled な span を仕掛けて、quality < 0.99 を assert、render shader が incoherent ket fallback を選ぶことを GPU snapshot で確認。
  9. GPU-only popup (readback 無し) (Playwright):
    1. 本番経路でホバーすると glyph overlay が表示されることを 1 expect
    2. frame ごとに read_amplitude_cell が呼ばれていないことを mock spy で 1 assert (本番 UI 経路は readback 禁止の確認)
    3. テスト専用 API read_amplitude_cell(gate_id, k) は async で動き、known-state で正しい値を返すことを 1 expect
  10. visual snapshot (本番の代表的描画) (insta, assert_snapshot! × 4) — 本番 cellPx を反映して: span 1 (full detail、cellPx ~ 40) / span 8 (needle 残る、cellPx ~ 27) / span 12 (needle 省略、outline + disk、cellPx ~ 10) / span 16 (needle なし、heatmap なし、円 SDF 経路は維持するが outline / disk は § 06 の半径閾値に従い点状または外枠だけに近い、cellPx ~ 3) の各フレームを 1 枚ずつ snapshot。回帰検出用 (heatmap モードはモック限定なので本番スナップショットでは扱わない)。
★ 批評 · § 11 テスト計画
「視覚デザインの正しさ」を検証するテストが visual snapshot 1 種類だけ

本仕様は GPU 計算の正しさ (known-state amplitude / Hermitian 性 / controls 統合 / phase lock 無効ケース) について豊富なテストを定義しているが、 「振幅表示ブロックがデザイン仕様どおりに描かれているか」を確認するテストは項目 10 の visual snapshot 4 枚だけ。 Flexoki Light 配色、cellPx 帯ごとのレイヤ抑制、incoherent 表現の alpha 0.45、phase 0 = 真上の方向、placeholder の purple-100 背景など、 本仕様の視覚的決定事項を直接テストする項目が無く、回帰検出が visual snapshot の人間レビューに依存している。

改善案: Playwright で本仕様ページ (docs/design-system/amplitude-display.html) 自体を開き、 モックの canvas をピクセル単位で読んで「指定 cell に blue-200 (#92BFDB) が描かれている」「placeholder セルに purple-100 (#ECE1F3) が描かれている」を assert するテストを追加する。 これは本仕様ページのモックが design-system.css / amplitude_render.wgsl / amplitude-display.html の 3 者で一貫していることを継続的に検証する仕組みになる。 AGENTS.md にも「デザインを修正したあとは必ず Playwright で実際の見た目を確認する」とあるので、自動化された Playwright assertion で「視覚仕様」の回帰を検出するのは整合的。

「1 ケース 1 アサーション」規約に対して visual snapshot 4 枚は過剰圧縮

項目 10 は 「span 1 / span 8 / span 12 / span 16」の 4 cellPx 帯を 4 個の assert_snapshot! で並べているが、それぞれの snapshot は full / needle 省略 / outline + disk / cellPx ≈ 3 の円 SDF + 半径閾値パスという 4 異なる描画パスを 1 枚に統合する。 snapshot が失敗したとき、原因が「cellPx 帯判定のバグ」なのか「個別レイヤ (outline / disk / needle) のバグ」なのか追跡しづらい。 AGENTS.md の「1 テスト 1 アサーション」規約に厳密に従うなら、cellPx 帯ごとに「outline が描かれているか」「disk が描かれているか」「needle が描かれているか」を別 case に分割する。snapshot ベースでこれを実現するなら、span 別 + レイヤ別の 12 枚程度に増やすほうが回帰原因の切り分けが容易。
