ParametricAngle 実装仕様

P / Rx / Ry / Rz の角度を、ただの文字列ではなく値オブジェクトとして扱うための仕様。 qni 互換の角度表記、URL 往復、WebGPU 実行計画、外部 Qiskit Aer 経路へ渡す JSON を同じ意味で扱うことを目的にする。

§ 01 背景と目的

導入前の Web 側では、配置済みゲートの角度は PlacedGate.angle: Option<String> として保持されていた。 そのため P() や不正な分数のような値も型上は混入でき、実行計画作成時に解析へ失敗すると π/2 に丸められる経路が残っていた。 一方、Qiskit バックエンドは Web 側と別の式解析器を持つため、同じ角度表記でも内部 WebGPU 実行と外部 Qiskit Aer 経路で振る舞いが分かれる恐れがある。

ParametricAngle は、生成できた時点で「qni 互換の角度として有効」と分かる値にする。 角度ラベル、URL 用表記、ラジアン値への変換を 1 か所に閉じ込め、String の受け渡しによる意味のずれを防ぐ。

  • 角度の妥当性検証は URL 復元時、パレット配置時、将来の角度入力確定時に行う
  • GPU シェーダや GateParams のバイナリ配置は変更しない
  • 量子状態、確率、ブロッホベクトルなどを CPU 側で計算しない既存規約は維持する
  • 本仕様の中心は Web 側 Rust コードだが、外部 Qiskit Aer 経路の整合には Python 製 Qiskit バックエンドの式解析器更新も含める。Rust の値オブジェクト自体は Python 側へ移植しない

§ 02 ソース走査結果

角度を扱う箇所を走査すると、必要な操作は「解析」だけではない。 URL 往復、ラベル表示、同角度判定、GPU 行列生成、外部 Qiskit Aer 経路との互換、TUI の入力確定がそれぞれ角度値へ別の要求を持つ。 ParametricAngle はこれらを 1 つの正規形から派生させる。

用途現状の参照箇所必要な操作

§ 03 ドメインモデル

型名ParametricAngle
配置先apps/web/src/gates/angle.rs を新設し、apps/web/src/gates.rs から再公開する
対象ゲートGateKind::Phase / GateKind::Rx / GateKind::Ry / GateKind::Rz
保持する値π に掛かる有理数係数。例: π/2 は 1/2、-π/128 は -1/128、2π/3 は 2/3、0 は 0/1
正規化生成時に最大公約数で約分し、分母は正にそろえた後、4π 周期で -2π < θ <= 2π に収める。4π/8 / 4/8π / π/2 はすべて同じ値になり、4π は 0、3π は -π になる
境界表記を一意にするため -2π は 2π に寄せる。2π は 0 にしない
不変性フィールドは非公開。生成後に係数を書き換えるメソッドは持たない
等価性約分済みかつ 4π 周期で正規化した係数で比較する。π_2、π/2、4π/8、4/8π は同じ値になる。4π と 0 も同じ値だが、2π と 0 は同じ値にしない

想定 API

#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub(crate) struct ParametricAngle {
    numerator: i32,
    denominator: NonZeroU32,
}

impl ParametricAngle {
    pub(crate) const DEFAULT_LABEL: &'static str = "π/2";

    pub(crate) fn parse_qni(input: &str) -> Result<Self, ParametricAngleError>;
    pub(crate) fn parse_user_input(input: &str) -> Result<Self, ParametricAngleError>;
    pub(crate) fn from_pi_fraction(numerator: i32, denominator: NonZeroU32) -> Self;
    // Default trait: ParametricAngle::default() == π/2
    pub(crate) fn label(&self) -> String;
    pub(crate) fn url_label(&self) -> String;
    pub(crate) fn radians_f32(&self) -> f32;
    pub(crate) fn numerator(&self) -> i32;
    pub(crate) fn denominator(&self) -> u32;
}

label() は保持文字列を返すのではなく、約分と 4π 周期正規化を終えた係数から qni 互換ラベルを組み立てる。 radians_f32() は GPU に渡す行列係数を作るための補助値を返すだけで、状態ベクトルの計算は行わない。 ParametricAngle が妥当性を保証するため、呼び出し側で unwrap_or(π/2) のような既定値への黙った置き換えをしてはならない。

§ 04 受け付ける角度表記

parse_qni は URL / JSON に現れる qni 互換表記を扱う。 前後の ASCII 空白を取り除き、URL から来る最初の _ だけを / に戻し、ちょうど 1 つの π を含む整数の有理数係数として検証する。 ただし 0 だけは π を含まない例外として受け付ける。 小数係数や符号付き分母は拒否し、0.5π は π/2、π/-2 は -π/2 のような正規形で表す。 約分後は 4π 周期で正規化し、係数を (-2, 2] に収める。 parse_user_input は角度入力 UI と TUI 互換のため、pi / PI、Unicode マイナス、空白除去を追加で許可する。 また、π を含まない整数または分数は π の係数として扱い、1/2 を π/2 に正規化する。 ただし小数係数と符号付き分母は入力 UI でも拒否し、妥当性検証は ParametricAngle だけで行う。

周期正規化は 4π 単位だけで行う。 Phase 単体は 2π 周期だが、Rx / Ry / Rz は行列として 4π 周期なので、共通値オブジェクトでは 2π を 0 にしない。 将来、Qiskit バックエンドと同じく π/2 + π/4 のような式を Web 側でも扱う場合は、ParametricAngle の文法を拡張してから受け入れる。 先に String で例外的に通す実装は作らない。

§ 05 組み込み方

配置済みゲート

PlacedGate.angle は Option<String> から Option<ParametricAngle> に変更する。 None は古い URL に含まれる裸の P / Rx / Ry / Rz を表すためだけに残す。 パレットから新規配置したパラメトリックゲートは必ず Some(ParametricAngle::default()) を持つ。

URL 往復

復元P(π_4) などの内側を ParametricAngle::parse_qni に渡す。失敗したトークンは不明トークンと同じ扱いで配置しない
生成angle.url_label() は、正規化済みラベル内の最初の / だけを _ に変換した URL 用表記を返す。呼び出し側はその値を使って P(π_4) のように出力する。P(4π_8) は復元後の再生成で P(π_2)、P(4π) は P(0)、P(3π) は P(-π) になる
裸トークンNone のときだけ P のように角度なしで出力する。新規配置から裸トークンは作らない

実行計画

simulation_plan::linearize_ops は、Some(angle) なら angle.radians_f32() を使って phase_params / rx_params / ry_params / rz_params を呼ぶ。 None の裸トークンだけ旧 URL 互換として π/2 の既定行列に進む。 Some の解析失敗を実行計画で扱う分岐は存在しない。

描画ラベルと Phase 接続線

角度ラベルは angle.label() を表示する。 裸トークンは表示上だけ ParametricAngle::default() (ParametricAngle::DEFAULT_LABEL 相当) を使う。 同じ列の Phase 接続線は、正規化済み係数の一致で束ねる。 これにより P(π_2)、P(π/2)、P(4π_8)、P(4/8π) は同じ角度として扱われる。 同様に P(4π) と P(0) は同じ角度として扱うが、P(2π) と P(0) は共通値オブジェクト上は同じ角度にしない。

外部 Qiskit Aer 経路

外部 Qiskit Aer 経路は既存どおり circuit_columns_to_json が作る列配列 JSON を columns に埋め込んで送る。 ParametricAngle は JSON スキーマを変えず、JSON 生成前に角度表記の妥当性を保証する。 例: 列配列は [["P(π_4)"]]、送信 JSON 内では {"columns":[["P(π_4)"]]}。 ただし 2π/3 のような qni の省略乗算表記は、現行の Python 側解析器ではそのまま解釈できない。 ParametricAngle を導入する実装では、Qiskit バックエンドを更新し、Web 側が送る正規化済みラベルを同じ角度として受け付けるようにする。 JSON スキーマは変えないため、columns の要素は文字列トークンのままにする。

§ 06 対象外

  • GateKind の値オブジェクト化は行わない。すでに enum で十分に制約できている
  • GateParams のフィールド型は変更しない。WebGPU へ渡す bytemuck::Pod 構造体として維持する
  • GPU シェーダ内で角度文字列を解釈しない。文字列処理は Rust 側の実行計画作成までに終える
  • Qiskit バックエンドの Python 実装に Rust の値オブジェクトを移植しない。ただし Web から送る qni 互換表記を同じ意味で受け付けることはテストで確認する
  • Phase 専用の 2π 周期正規化は行わない。ParametricAngle は Phase / Rx / Ry / Rz の共通値として 4π 周期でだけ正規化する
  • QFT / QFT† の内部分解で作る制御 Phase の角度は、URL ラベルやユーザー入力を持たない実行計画内の一時値なので ParametricAngle へ置き換えない
  • 状態表示や表示ブロックのシェーダ内で計算する振幅の位相角は、回路ゲートの入力角度ではないので ParametricAngle の対象外にする
  • ワイヤ番号、列番号、span の値オブジェクト化は別検討にする

§ 07 受け入れ条件

  1. 妥当な角度を生成できる — π / +π / -π / π/2 / π_2 / 2π/3 / 0 が ParametricAngle になることを、各入力ごとに 1 ケース 1 アサーションで確認する
  2. 約分される — 4π/8 / 4/8π / -6π/9 / 0π/8 が、それぞれ π/2 / π/2 / -2π/3 / 0 へ正規化されることを、各入力ごとに確認する
  3. 4π 周期で正規化される — 4π / -4π / 6π / 3π が、それぞれ 0 / 0 / 2π / -π へ正規化されることを、各入力ごとに確認する
  4. 2π 周期では正規化しない — 8π/4 が 2π になり、0 にはならないことを確認する
  5. 境界は 2π 側へ寄せる — -2π が 2π へ正規化されることを確認する
  6. 不正な角度を拒否する — 空文字 / π/0 / 1.0 / 0.5π / π/-2 / abc / ππ が Err になることを、各入力ごとに確認する。P() は内側が空文字の例として扱う
  7. URL 表記を正規化する — π_2 を復元すると label() == "π/2" になり、生成時は url_label() == "π_2" になることを別々のテストで確認する
  8. 約分・周期正規化後の URL が安定する — P(4π_8) を復元して再生成すると P(π_2) になること、P(4π) を復元して再生成すると P(0) になることを別々のテストで確認する
  9. 同角度判定が正規化係数で行われる — π/2 と 4π/8 が同じ値として扱われること、4π と 0 が同じ値として扱われること、2π と 0 は異なる値として扱われることを別々のテストで確認する
  10. ラジアン値が正しい — π/2 / -2π/3 / 4π / 6π の radians_f32() が、それぞれ PI / 2 / -2 * PI / 3 / 0 / 2 * PI に近いことを各入力ごとに確認する
  11. ユーザー入力互換を保つ — parse_user_input("pi / 2") / parse_user_input("PI/2") / parse_user_input("1/2") が π/2 になることを、各入力ごとに確認する
  12. 旧 URL の裸トークンを保つ — {"cols":[["P"]]} / {"cols":[["Rx"]]} / {"cols":[["Ry"]]} / {"cols":[["Rz"]]} を復元した場合は angle == None のままにすること、表示では π/2 として扱うこと、実行では π/2 として扱うこと、再生成も裸トークンになることをゲート種別と観点ごとに別々のテストで確認する
  13. 新規パレット配置は明示角度を持つ — Phase / Rx / Ry / Rz のパレット配置が Some(ParametricAngle::default()) になり、URL は P(π_2) などになることを各ゲートごとに確認する
  14. 不正角度は既定値に化けない — {"cols":[["P()"]]} や {"cols":[["P(π_0)"]]} を復元しても π/2 の Phase ゲートとして配置されないことを確認する
  15. 実行計画で再解析失敗分岐がない — linearize_ops 内から parse_angle_radians(...).unwrap_or(...) が消え、ParametricAngle から得たラジアン値だけを使うことを確認する
  16. 外部 Qiskit Aer 経路と意味が一致する — ParametricAngle 導入後も P(π_4) / Rx(π_2) / P(2π_3) などの列配列 JSON が Qiskit バックエンドで同じ角度として受理されることを確認する
